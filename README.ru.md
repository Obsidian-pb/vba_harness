# VBA-Harness

**[English](README.md)** | **Русский**

LLM-харнес для программирования на VBA — агентный фреймворк для написания кода, полностью работающий внутри Microsoft Office VBA.

## Обзор

В наши дни программирование с помощью LLM-агентов стало обыденностью. Однако Visual Basic for Applications (VBA), будучи тесно интегрированным в приложения Microsoft Office, не предоставляет внешним инструментам простого доступа к программному коду. Стандартные подходы, используемые современными харнесами, серьёзно ограничены — пользователю приходится вручную копировать код между чатом LLM и редактором VBA.

Тем не менее VBA остаётся популярным и широко используемым языком программирования. Для упрощения разработки макросов VBA с применением современных агентных подходов был создан этот мини-харнес. Он сам является VBA-приложением, способным запускать цикл агента и выполнять действия через набор инструментов.

Пользователи также могут разрабатывать собственные инструменты для решения задач, выходящих за рамки программирования — например, форматирование документов Word, вычисления в ячейках Excel, запросы к базам данных Access или манипуляции фигурами Visio.

Примеры реализации харнеса для различных приложений Microsoft расположены в папке `apps/`.

## Архитектура

Проект следует модульной, инструментально-ориентированной архитектуре. Весь исходный код находится в папке `code/`.

### Основные классы

| Файл | Роль |
|---|---|
| `clsHarness` | Главный LLM-агент — история сообщений, цикл вызова инструментов, HTTP-обмен |
| `clsHarnessConsole` | Консольный запуск агента для отладки через окно Immediate |
| `clsHarnessToolsHandler` | Реестр и диспетчер инструментов — регистрирует доступные инструменты, генерирует JSON-схему `tools[]` для LLM и диспетчеризует вызовы инструментов по имени |
| `clsToolBase` | Абстрактный базовый класс для всех инструментов — определяет интерфейс `Name`, `Description`, `Schema` и `Execute` |
| `c_buttons` | Класс-обработчик событий нажатия кнопок панели инструментов |

### Встроенные инструменты

Каждый инструмент реализует `clsToolBase` и регистрируется в `clsHarnessToolsHandler.Init()`:

| Инструмент | Внутреннее имя | Описание |
|---|---|---|
| `clsTool_GetProjecCode` | `get_module_vba_code` | Возвращает VBA-код всего проекта или конкретного модуля |
| `clsTool_AddModule` | `add_module` | Создаёт новый VBA-компонент (стандартный модуль, класс или пользовательскую форму) с опциональным начальным кодом |
| `clsTool_GetSelectedCode` | `get_selected_code` | Возвращает выделенный код из активного окна редактора VBA (или весь модуль, если ничего не выделено) |
| `clsTool_ListProjects` | `list_vba_projects` | Список всех открытых VBA-проектов и их компонентов (только структура, без кода) |
| `clsTool_ReplaceCodeRange` | `replace_code_range` | Заменяет VBA-код в указанном диапазоне строк с поддержкой отмены |
| `clsTool_WriteTextFile` | `write_text_file` | Записывает текстовое содержимое в файл (кодировка UTF-8) |
| `clsTool_ReadTextFile` | `read_text_file` | Читает текстовый файл и возвращает его содержимое (кодировка UTF-8) |

### Вспомогательные модули

| Файл | Назначение |
|---|---|
| `m_Constants` | Глобальные константы — `HARNESS_NAME`, пути к ключам реестра, переключение режима отладки |
| `m_code` | Утилиты для работы с кодом VBA-проектов — получение кода модуля, выделенного кода, поиск проекта по имени |
| `m_FileIO` | Помощники файлового ввода-вывода (чтение/запись UTF-8, разрешение путей) |
| `m_json` | Помощники построения и разбора JSON (`JsonString`, `ExtractJsonString`, `CollectionToJsonArray`) |
| `m_toolbar` | Управление панелью инструментов — `AddTB_LLM` и `RemoveTB_LLM` |
| `m_Utils` | Общие утилиты — чтение/запись реестра (`GetSettingFromRegistry`), логирование |
| `m_tests` | Модульные тесты для инструментов и утилит |

### Формы интерфейса

| Файл | Назначение |
|---|---|
| `LLM_chat_html` | Диалог чата на основе HTML для взаимодействия с LLM |
| `LLM_config` | Форма настроек для конфигурации параметров API LLM |

## Как работает цикл агента

1. Пользователь вводит промпт.
2. `clsHarness.AgentLoop` добавляет системный промпт и сообщение пользователя в историю сообщений, затем входит в цикл (до `agent_max_turns`, по умолчанию 30):
   - Отправляет полную историю сообщений и список зарегистрированных инструментов в API LLM через `MSXML2.ServerXMLHTTP`.
   - Если ответ содержит `tool_calls`, каждый инструмент выполняется через `clsHarnessToolsHandler.Execute`, а результат добавляется в историю как сообщение `role: "tool"`.
   - Если ответ не содержит вызовов инструментов, он считается окончательным ответом, и цикл завершается.
3. На протяжении всего процесса генерируются события: `OnThinking`, `OnReasoning`, `OnToolCalling`, `OnAnswer`, `OnSystem`, `OnTick`.

## Почему не VSTO

Более «правильный» с инженерной точки зрения подход — создать отдельный надстройку для Microsoft Office с использованием Visual Studio Tools for Office (VSTO). Однако это потребовало бы разработки и поддержки множества различных версий надстройки — по одной для каждого приложения Office и, возможно, для каждого года выпуска.

Использование для этой задачи самого VBA — это, бесспорно, скорее «кустарный» подход, но он же и гораздо более универсальный — единая кодовая база, адаптируемая с минимальными изменениями к каждому приложению-хосту.

---

## Известные ограничения

VBA весьма требователен к изменению кода, который выполняется в данный момент (это не Python). Если вы решите использовать VBA-Harness для улучшения его собственного исходного кода, настоятельно рекомендуется сначала сделать копию проекта харнеса и работать с копией. Кроме того, временно переименуйте VBA-проект копии во что-то отличное от `HARNESS` (имя хранится в константе `HARNESS_NAME`). После завершения изменений переименуйте проект обратно в `HARNESS`.

---

## Добавление в собственное решение

В большинстве случаев достаточно:

1. Импортировать все модули из папки `code/` в ваш VBA-проект.
2. Адаптировать модуль `ThisDocument` под модель событий вашего приложения-хоста (см. `apps/visio/` для примера).
3. Убедиться, что проект назван `HARNESS`, либо обновить константу `HARNESS_NAME` соответствующим образом.

## Использование

### Панель инструментов

Модуль `m_toolbar` предоставляет две процедуры:

- `AddTB_LLM` — добавляет панель инструментов **LLM** с кнопками **Чат** и **Настройки**.
- `RemoveTB_LLM` — удаляет панель инструментов.

![](imgs/toolbar.jpg)

Наиболее удобный подход — привязать их к событиям открытия/закрытия документа:

```vb
Private Sub Document_DocumentOpened(ByVal doc As IVDocument)
    AddTB_LLM
End Sub

Private Sub Document_BeforeDocumentClose(ByVal doc As IVDocument)
    RemoveTB_LLM
End Sub
```

### Конфигурация LLM

Используйте форму **Настройки** (`LLM_config`) для конфигурации следующих параметров (хранятся в реестре Windows под `HKCU\Software\LLMRedactorMacro\`):

| Параметр | Ключ реестра | Описание |
|---|---|---|
| API-эндпоинт | `LLM_API_URL` | URL API LLM (OpenAI-совместимый) |
| Основная модель | `LLM_MODEL_ID` | Идентификатор модели для цикла агента |
| Быстрая модель | `LLM_MODEL_FAST_ID` | Идентификатор лёгкой модели (зарезервировано для будущего использования) |
| API-ключ | `LLM_API_KEY` | Ключ аутентификации |
| Системный промпт | `LLM_SYSTEM_PROMPT` | Строка системной инструкции |

![](imgs/llm_settings.jpg)

### Диалог чата

Форма **Чат** (`LLM_chat_html`) предоставляет HTML-интерфейс для взаимодействия с LLM. Из этого диалога пользователь также может:

- Загружать текстовые файлы как контекст (используется инструмент `read_text_file`).
- Очищать контекст беседы.

![](imgs/chat_dialog.jpg)

## Сценарии использования

Ниже приведены примеры промптов для харнеса при решении типовых задач. Каждый сценарий показывает пользовательский промпт и краткое описание того, какие инструменты использует агент.

### Написание кода с нуля

**Промпт:**
> Напиши модуль `m_StringUtils` с функциями `TrimAll(s As String) As String` (удаляет все пробелы) и `CountWords(s As String) As Long` (считает слова). Добавь комментарии к каждой функции.

**Что происходит:** агент вызывает `add_module` для создания нового стандартного модуля `m_StringUtils` с указанным кодом, затем `get_module_vba_code` для проверки результата.

---

### Редактирование существующего кода

**Промпт:**
> В модуле `m_FileIO` обнови функцию `ReadAllText` — добавь параметр кодировки вторым аргументом (`Optional Encoding As String = "UTF-8"`).

**Что происходит:** агент вызывает `get_module_vba_code` для получения текущего кода `m_FileIO`, находит целевую функцию, затем использует `replace_code_range` для замены строк сигнатуры и тела.

---

### Редактирование по диапазону строк

**Промпт:**
> В модуле `m_Utils`, строки 12–18, замени вызов `MsgBox` на запись в лог через `Debug.Print`.

**Что происходит:** агент вызывает `replace_code_range` с параметрами `project:="HARNESS"`, `module:="m_Utils"`, `start_line:=12`, `end_line:=18` и новым кодом.

---

### Чтение файла с диска

**Промпт:**
> Прочитай файл `C:\Data\config.json` и покажи его содержимое.

**Что происходит:** агент вызывает `read_text_file` с путём `C:\Data\config.json`, получает содержимое и отображает его пользователю.

---

### Сохранение сгенерированного кода в файл

**Промпт:**
> Сохрани код модуля `m_StringUtils` в `C:\Export\StringUtils.bas`.

**Что происходит:** агент вызывает `get_module_vba_code` для получения кода модуля, затем `write_text_file` с путём `C:\Export\StringUtils.bas` и полученным содержимым.

---

### Сложный сценарий: аудит и исправление

**Промпт:**
> Найди все модули в проекте `HARNESS`, которые используют `On Error Resume Next`, и замени их на корректную обработку ошибок через `On Error GoTo`. Сохрани результаты в `C:\Reports\audit_log.txt`.

**Что происходит:**
1. `list_vba_projects` — получает список всех модулей проекта.
2. `get_module_vba_code` — читает каждый модуль по очереди.
3. `replace_code_range` — заменяет найденные конструкции в каждом модуле.
4. `write_text_file` — сохраняет отчёт о внесённых изменениях.

---

### Работа с выделенным кодом

**Промпт:**
> Я выделил несколько функций в редакторе VBA. Выполни их рефакторинг: вынеси повторяющуюся логику в отдельную приватную функцию `ValidateInput`.

**Что происходит:** агент вызывает `get_selected_code`, получает выделенный фрагмент, анализирует его и применяет изменения к соответствующему модулю через `replace_code_range`.

## Расширение собственными инструментами

Чтобы добавить новый инструмент:

1. Создайте новый модуль класса с `Implements clsToolBase`.
2. Реализуйте четыре члена интерфейса: `clsToolBase_Name`, `clsToolBase_Description`, `clsToolBase_Schema` и `clsToolBase_Execute`.
3. Зарегистрируйте инструмент в `clsHarnessToolsHandler.Init()`.

Собственные инструменты могут делать всё, что может VBA — манипулировать документами Office, делать запросы к базам данных, вызывать внешние API или выполнять файловые операции.
